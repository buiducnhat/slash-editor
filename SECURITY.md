# Security Policy

## Reporting Vulnerabilities

If you discover a security vulnerability in slash-editor, please report it responsibly.
We appreciate your help in keeping users safe.

**Please do not report security vulnerabilities through public GitHub issues.**

Send details to: **nhat@buiducnhat.com**

Include a description of the vulnerability, steps to reproduce, and any potential impact.
We will acknowledge receipt within 48 hours and provide updates as we investigate.

## Response Process

Vulnerabilities are assessed and prioritized based on severity, exploitability, and business impact.
Fixes are deployed according to the following timelines:

| Severity     | Examples                             | Timeline                           |
| ------------ | ------------------------------------ | ---------------------------------- |
| **Critical** | Remote code execution, data breaches | Fixed and released within 24 hours |
| **High**     | Significant data exposure            | Fixed and released within 72 hours |
| **Medium**   | Moderate information leaks           | Fixed and released within 14 days  |
| **Low**      | Minor issues, edge cases             | Addressed in next scheduled update |

## Scope

This policy applies to all slash-editor packages (`@slash-editor/core`, `@slash-editor/react`)
and the registry infrastructure. Reports are handled through our vulnerability management process.

## Disclosure

We follow responsible disclosure practices. We will credit reporters unless requested otherwise.
