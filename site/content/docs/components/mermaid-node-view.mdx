## Usage

`createBlockKit` registers the `mermaid` node by default, without a `NodeView` it renders as a
plain `<pre>`. Opt the default out and append one with the view:

```tsx
import { Mermaid } from "@slash-editor/core";
import { ReactNodeViewRenderer } from "@tiptap/react";
import { MermaidNodeView } from "@/components/nodes/mermaid-node-view";

const editor = useSlashEditor({
  blockKit: {
    mermaid: false,
    extend: [Mermaid.extend({ addNodeView: () => ReactNodeViewRenderer(MermaidNodeView) })],
  },
});
```

## Behaviour

- **Source is document text.** The diagram's source is the node's own text, not an attribute, so
  undo, IME, and collaborative editing merge it character by character like any code block.
- **Lazy.** `mermaid` is imported the first time a diagram renders, in the browser only.
- **Themed.** Colours and font come from your tokens (`--secondary`, `--ring`,
  `--muted-foreground`, `--chart-1`…`--chart-5`, …) and re-render when the theme switches.
- **Safe.** Rendering uses Mermaid's `securityLevel: "strict"`; a `%%{init}%%` directive in the
  source cannot lower it.
- **Errors.** A parse error shows Mermaid's message under the last diagram that rendered.
- **Markdown.** With `@slash-editor/core/markdown`, the block exports as a ` ```mermaid ` fence
  (GitHub renders it) and imports back as a diagram.
